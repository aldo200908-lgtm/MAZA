# MAZA Web — diseño aprobado
El usuario aprobó implementar la revisión de dos caras y aclaró que esta entrega es solo web. La app se desarrollará aparte; no se modifica Android ni se genera APK.
Público: inicio con presentación/buscador, barbería/reservar, productos, alquileres y cuenta. Cinco destinos, celular primero; cabecera en escritorio. Reservar: servicio → turno → confirmar, datos previos si existen. Cuenta/historial propios, confirmación, cancelar/reprogramar citas futuras y solicitudes de productos/alquileres sin cobros.
Administrador: resumen, citas y gestión en móvil; menú lateral en escritorio. Rutas /admin separadas, clientes/historial y configuración. Catálogos y solicitudes visibles en panel; no pasarela ni movimientos financieros simulados como reales.
Flutter Web con go_router 16.2.4 (compatible con Flutter 3.35.7). Dos StatefulShellRoute, rutas hash compatibles con GitHub Pages. Redirecciones seguras y revalidación de disponibilidad. Supabase usa RPC y RLS: catálogo público sin clientes, perfil vinculado a auth.uid(), historial propio y administrador único. La demo muestra explícitamente accesos de ejemplo y persistencia por navegador, sin fingir autenticación real.
Se reutilizan reglas y módulos de administración existentes. Los registros demo del nuevo cliente y sus solicitudes se guardan; roles demo nunca son roles Supabase. No publicar datos privados ni claves.
